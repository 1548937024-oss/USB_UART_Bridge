# AGENTS.md

本文件适用于 `PRO_X20P_DRIVER_V1.01` 仓库中的 Altium 到 KiCad 转换工程。
Codex 在本仓库执行原理图、PCB、封装、导出和检查任务时必须遵守以下规范。

通用原理图和 PCB 设计基线见上一层仓库：

`../docs/KiCad_Schematic_PCB_Design_Spec.md`

本文件其余内容属于当前项目专属增量规则。通用规范与本文件冲突时，以当前项目
更严格的要求、数据手册和安规约束为准。

## KiCad 原理图通用规则

- 不使用强制统一器件方向；二端器件按其电流方向和自然走线旋转。
- 走线不得穿过器件本体；不同网络的走线尽量不交叉。
- 电源符号放在图面上方或左侧，GND 符号放在图面下方或右侧。
- 电源符号的 Value 隐藏，避免干扰阅读。
- `PWR_FLAG` 使用带可见旗形轮廓的符号，便于辨识；参考 `#FLG07` 样式。
- 元件 Reference 与 Value 不得放在同一行或同一列，两者应错开布局，避免文字重叠。

## 环境约束

- 优先使用本机 `D:\KiCad10.0` 中的 KiCad 10。
- 如果首选路径不存在，再检测 `C:\Program Files\KiCad\10.0`。
- 自动检查和导出优先使用 `kicad-cli`。
- 需要操作电路板对象时使用 KiCad 安装目录中的 `pcbnew` Python API。
- 不在 `.kicad_sch`、`.kicad_pro` 或脚本中硬编码 KiCad 安装路径、临时目录和
  用户私有路径。
- 原理图格式升级必须使用当前安装版本，并通过 `kicad-cli sch upgrade --force`
  执行；升级前先确认 Git 基线，保证文件头和数据变化可审核。

## 修改前检查

每次开始原理图或 PCB 工作前：

1. 检查 Git 工作区是否干净，并确认当前分支和最近提交。
2. 核对 `.kicad_pro`、顶层 `.kicad_sch` 和各子图纸的实际文件名及层次引用。
3. 运行一次 ERC，记录现有错误和警告，不得把转换遗留问题误报为本次新增。
4. 确认封装库、符号库和 3D 模型路径可以解析。
5. 明确本次修改的模块边界、电气网络和验收条件。

发现已有未提交改动时，先判断其来源并保留；不要回滚用户或 KiCad 自动生成的
改动。

## 原理图层次结构

- 顶层图纸只放外部接口、跨图纸端口和主要电源流向。
- `POWER` 页负责输入保护、电源转换、基准和对应去耦。
- `MCU` 页负责 MCU 最小系统、时钟、复位、调试和控制信号。
- `ENCODER` 页负责编码器供电、接口、滤波和保护。
- `Conmunication` 页负责通信接口、收发链路和保护；修正该名称时同步更新
  层次页引用和文档。
- `MOTOR` 页负责驱动器、功率级、栅极回路、采样和功率接口。
- 跨图纸信号必须使用层次标签和图纸引脚连接。
- 电源网络必须使用 `power` 库中的电源符号，不得用普通网络标签代替。
- 修改层次结构时，同时更新层次页引用、图纸引脚、全局连接关系和 ERC 结果。

## 通信页特殊约束

- `CANH/CANL` 为 `5 Mbps` CAN 差分总线，原理图中必须明确标注使用差分走线。
- `D1`（SM712）在 PCB 上必须靠近 CAN 接口放置，ESD 保护支路应尽量短。
- `CANFD1-TX` 和 `CANFD1-RX` 属于高速关键信号，PCB 布线时必须优先布线，
  并保持回流路径和参考平面连续。

## 原理图可读性

- 信号流向统一为左进右出、上进下出。
- 每页优先保持 2 至 4 个主功能块，最多不超过 5 个。
- 电源网络放在图面上方或左侧，GND 网络放在下方或右侧。
- 器件按信号或电流流向排列，模块之间保留清晰留白。
- 功能框必须覆盖该模块的器件、关键引脚、去耦、测试点和必要注释。
- 器件原点、引脚、走线端点、网络标签和 no-connect 必须落在 KiCad 默认
  `1.27 mm` 栅格上。
- 禁止半格坐标和任意小数坐标。
- 连线只允许水平和垂直段，禁止 `45°` 折线、任意角度斜线、重叠和跨器件走线。
- 同一页不同网络的交叉应尽量为零；跨模块连接优先改用同名标签或层次端口。
- 网络标签优先放在实际走线上，孤立网络的引线不超过 `2.54 mm`。
- 二端器件允许旋转 `90°/180°/270°`，以电流方向和自然走线为先。
- 去耦电容必须紧邻对应电源和地引脚，并优先形成最短回流路径。

## 命名与网络

- 网络名使用 `功能_方向_目标` 或 `功能_电压_序号_信号` 格式。
- 低有效信号使用 `n` 前缀，例如 `nRST`、`nCS`。
- 禁止 `NET001`、单字母、`DATA` 等无语义或重复标签。
- 同一电压网络全工程统一命名，例如 `PWR_3V3`、`PWR_5V`、`PWR_12V`；
  禁止混用 `VCC`、`VDD`、`3V3`。
- 按用途区分地网络，例如 `GND`、`AGND`、`PGND`；存在隔离设计时使用
  `ISO_GND`，不得擅自把不同地网络合并。
- 页间信号优先使用层次端口。Global Label 仅用于电源、地和确有全局必要的信号。
- 未使用引脚必须显式放置 `no_connect`。
- `PWR_FLAG` 只用于向 ERC 声明外部供电或由无源器件供电的网络，不是转换器、
  接地符号或电气连接器件。

## 注释与测试

- 每个 IC 旁标注型号、关键参数和封装。
- 跳线、配置电阻和模式选择必须注明默认状态与可选项。
- 关键电源、通信、栅极驱动、采样和调试信号应放置测试点。
- 测试点需写明预期电压、速率、容差或测试条件。
- 首页保留电源流向说明和修订表：`Rev / Date / Author / Changes`。
- 所有器件、注释、测试点和模块框必须位于图纸有效边框内。

## PCB 约束

- PCB 的层数、板厚、铜厚、最小线宽、最小间距和最小钻孔必须从原始 PCB、
  制造要求和机械要求中核实，不得凭其他项目直接套用。
- 原始 Altium PCB 是层叠、机械结构、封装位置和关键约束的重要参考。
- 高电流路径优先短、宽、连续，并检查回流路径和过孔载流能力。
- 栅极驱动回路、功率回路和采样回路必须控制面积，采样优先使用 Kelvin 连接。
- 发热器件需要核对铜面积、散热过孔、器件间距和温度降额。
- 差分对必须同层、短距离、等长，并保持参考平面连续。
- 自动布线不得跨越安全隔离、危险电压区、功率环路或用户明确指定的禁止区域。
- 仓库中出现可用 `.kicad_pcb` 后，先完成设计规则、叠层和机械边界确认，再布线。

## 自动化工作流

设计变更应尽可能可重复、可审核。标准流程：

1. 先建立或更新 Git 基线。
2. 修改工程源文件或生成脚本。
3. 运行原理图格式升级。
4. 运行 ERC。
5. 导出网表、BOM、PDF 或必要的制造文件。
6. 检查未连接项、网络交叉、封装字段和库引用。
7. 审核 Git diff。
8. 提交一个逻辑完整、可回退的变更集。

常用 KiCad 10 命令模板：

```powershell
& 'D:\KiCad10.0\bin\kicad-cli.exe' sch upgrade --force .\PRO_X20P_DRIVER_V1.01.kicad_sch
& 'D:\KiCad10.0\bin\kicad-cli.exe' sch erc .\PRO_X20P_DRIVER_V1.01.kicad_sch
```

具体导出参数以当前安装的 `kicad-cli --help` 输出为准。不得在未运行命令的情况下
声称 ERC、DRC、网表、BOM 或制造导出已经通过。

## 发布关口

- G0 环境：KiCad CLI 和 `pcbnew` 可用。
- G1 需求：需求可测试且无歧义。
- G2 架构：器件、封装、电源、复位和接口已验证。
- G3 原理图：层次引用正确，ERC 零错误，警告逐条确认，网表和 BOM 已生成。
- G4 布局：机械配合、安装、热设计和关键器件位置已验证。
- G5 布线：连通性、功率回流、栅极回路、采样和差分约束已验证。
- G6 DRC：DRC 和原理图一致性检查通过。
- G7 制造：Gerber、钻孔、坐标和必要的 STEP 文件完整。
- G8 发布：干净环境可复现，输出可追溯。

- 纳入源码：`.kicad_pro`、`.kicad_sch`、`.kicad_pcb`、库表、封装库、符号库、

- 不提交未经说明的临时导出、缓存、编辑器备份或本地历史仓库。
- 提交前使用 `git diff --cached` 检查内容；二进制库文件变动必须说明原因。
- 未获得用户明确要求时，不创建远程仓库、不推送、不改写提交历史。

## 安全和审核边界

- 不自动签署 EMC、安规、热设计、功能安全或高速信号完整性结论。
- 不在缺少数据手册、机械尺寸、制造规则和测试结果时宣称设计可生产。
- 不依靠导入转换结果推定器件参数、封装尺寸或网络连接一定正确。
- 不跨越危险电压区或隔离带自动布线。
- 不把不同地网络连接为同一网络。
- 不把总线电压选项误解为逻辑电平要求。

## MicroDriver V2.10 专属绘制规则（必读）

本项目在 ENCODER 页绘制过程中确认了一批硬性规则与工作方法，全部记录在
`docs/V2.10_绘制规则.md`。绘制 POWER / MCU / communication / MOTOR / TOP
各页之前必须先读该文件，其中关键几条：

- 一条网络只放一个 `PWR_FLAG`；支线搭干线必须画 `junction`。
- 落线前先用 `Libraries.pin_positions()` 探测真实引脚坐标，不要推算。
- 标号对齐跟随旋转角自动（已由 `scripts/kicad_lib.py` 的
  `auto_justify()` 统一处理），不得逐页硬编码。
- 保护件贴被保护侧（ESD 在串阻之前），滤波件贴被滤波侧
  （RC 电容在串阻之后）。
- ERC 报告按 `***** Sheet` 分段读，逐条定位器件与坐标。
- 每页交付前跑闭环：生成 → `sch upgrade` → 分页读 ERC →
  导出 PDF 渲染 → 人工复核。
